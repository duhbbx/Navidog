# 0.36 SQL 语义、转换、本地优化与执行计划

查询页增加“本地优化…”；原“解释”增加独立的“计划树”。SQL 分析不执行查询、不自动创建索引或改写编辑器。源 SQL、连接、事务和未保存草稿保持各自边界。

## 本地关系优化器

独立 C++17 库 `navidog_sql_optimizer` 消费 owning SQL Model，建立关系代数 DAG，再用有界 Memo 等价组、规则和按排序性质区分的动态规划比较物理候选。借鉴 Calcite VolcanoPlanner 的公开架构，原生重实现这一批核心概念；没有把全部 Java Calcite、执行引擎、适配器和规则移植过来。

覆盖扫描、过滤、内 / 外连接、聚合、投影、排序、分页、窗口、派生表 / CTE / 子查询依赖、集合查询和普通 DML 的关系表示。规则包括内连接交换 / 结合与安全的过滤下推；外连接、USING / NATURAL 合并列和不能证明可移动的表达式作为边界。比较表 / 索引访问、循环 / 哈希连接、哈希 / 排序聚合、Top-N 和集合算法。选择率估计保留 TRUE / FALSE / UNKNOWN，覆盖 NOT、NULL、安全等值与简单 IN；列相关性仍以假设标记。没有执行这些物理算子的独立数据库运行时。

报告包含逻辑关系 DAG、物理候选、规则、实际使用的统计 / 来源和有效预算 / 权重。索引建议只由必须满足的同域条件形成有限前导键候选，不组合 OR 分支，也不计入假设收益或自动建索引。

分析弹窗左侧是 SQL 副本与表统计，右侧是候选 / 基线计划、建议、规则轨迹和 JSON。手工修改行数 / 平均行宽可保存到本地 SQLite；不修改服务端统计。设置中的“SQL 分析与优化”统一管理默认行数、算子内存、Memo / 时间预算、相对权重与三类规则。窄窗口查询工具条通过“更多”保留所有命令入口。

成本单位是 CPU、页 I/O 与内存的通用相对量。不是毫秒，也不能与数据库 EXPLAIN 的 COST 跨系统比较。选择率、相关性、行宽、重复值等仍有启发式假设；没有直方图、多列相关性、服务端完整类型 / 排序规则、并行 / 分布式调度或完整去相关器。搜索达到预算时明确标记，不宣称全局最优或服务端一定采用候选方案。

## 目录统计和存储

在已有的已连接数据库后台元数据同步中，批量读取 PG / MySQL / Oracle / SQL Server 系统目录的估计行数、行宽、列 NDV / NULL 比例（可用时）和索引键。SQLite 仅复用已有 sqlite_stat1，不自动 ANALYZE。读取器不 COUNT 整张业务表，不采样业务行，不收集直方图值。

统计与结构目录同代原子替换，按连接身份 / 数据库 / Schema 隔离；TTL、DDL / 事务失效、未验证磁盘缓存和权限失败保持保守策略。统计不可得不会使名称校验失效。索引定义截断时整批不用于唯一性判断，部分 / 表达式索引等不假设成普通全表索引。单表和整体缓存均有限额。

## 语法与语义

- 命名窗口 WINDOW / OVER name / 继承与展开，保留定义和源位置；验证重复 / 未定义 / 循环引用及覆盖规则。PG 与 MySQL 的前向引用规则分别处理。Oracle / SQL Server 的新版本命名窗口尚未在默认旧版本基线上启用。
- UNION / ALL、INTERSECT、EXCEPT / Oracle MINUS 的树形 AST / IR，方言优先级、括号、结果列数和输出排序作用域；集合查询可用于 CTE、子查询、INSERT SELECT 和视图来源。MySQL INTERSECT / EXCEPT 需要 8.0.31+；ALL 的能力按方言限制。SQLite 复杂分组集合仍可能要求手工派生表包装。
- PG / SQLite 聚合 FILTER 的类型化包装节点，支持普通聚合和窗口聚合；过滤条件单独校验，不允许嵌套聚合 / 窗口，已知标量函数不能套用 FILTER。
- GROUP BY / HAVING / ORDER BY 的输出别名按方言和子句绑定，保留输入字段与输出别名的不同优先级；MySQL HAVING 进一步尊重分组列优先规则。
- 窗口 / 聚合函数位置、嵌套、常见参数个数、窗口边界和方言限制检查。PG 的 ROWS / GROUPS 数字转换不机械沿用其他方言规则。
- 局部变量、参数、嵌套块、声明位置和同名覆盖使用程序作用域 / 符号 ID；嵌入 SQL 现在接收当前目录和数据库 / Schema。MySQL 变量优先、Oracle 列优先、PL/pgSQL 默认冲突报错分开处理；没有完整目录时不猜测有歧义的绑定。赋值左侧仍按目标列绑定。
- 元数据完整类型名与无歧义函数返回类型参与类型族推断，point / interval / integer[] 不按子串误判成整数。条件表达式检查保留 PG 未定字符串字面量的隐式类型能力。
- 基础类型族与 SELECT 输出别名引用进入统一模型，供派生输出、补全和分析使用。这不是完整隐式类型转换 / 重载选择系统。
- 编辑器复用过程编译与脚本检查，支持客户端 DELIMITER / GO / Oracle 单独斜线的分析副本；原文和执行文本不被改动。

函数 / 过程的游标、异常、动态 SQL、复杂返回约定、包、触发器转换，递归 CTE、MERGE、复杂类型 / 权限等仍需后续覆盖。不把未覆盖语法当成服务器一定不支持。

## 转换

跨方言转换保持整批原子输出、明确的能力诊断与目标前端重解析。新增集合结构、FILTER 和命名窗口展开；跨方言按需要展开有目录证明的 GROUP / HAVING 输出别名。当前连接的只读元数据上下文可传入转换弹窗；切换源方言后不复用不匹配目录。已知的字符串运算、混合类型比较 / CASE / COALESCE、条件和过程赋值 / RETURN 的隐式转换差异会明确拒绝，不能用目标重新解析替代语义等价证明；窗口内部与最外层排序都保留 NULL 顺序，无法证明等价时拒绝。普通无来源 SELECT 生成 Oracle SQL 时使用 SYS.DUAL，显式 SYS.DUAL 的常量查询可在适当目标中移除。

函数 / 过程仍通过独立的程序 AST → 带符号绑定的 owning Model → 目标生成处理。DDL 的隐式提交差异继续要求显式审核。目标解析通过只证明已覆盖的语法 / 语义检查通过，不等于已经验证所有服务器版本、目标对象、运行数据、精度、排序规则、触发器与权限的等价性。

## 服务端估计计划

PG EXPLAIN JSON、MySQL FORMAT=JSON（含新版 query_plan）、SQL Server SHOWPLAN_XML、Oracle PLAN_TABLE 的 ID / PARENT_ID 行、SQLite EXPLAIN QUERY PLAN 统一为算子树。点击查看估计行数、服务端 COST、索引、条件和原始属性；支持导出统一 JSON 和可用的原始 JSON / XML，保留结果网格。

使用独立会话查看估计计划，不运行 EXPLAIN ANALYZE。Oracle 的临时计划行回滚，SQL Server 的 SHOWPLAN 会话在完成 / 错误 / 取消后丢弃，不污染查询事务。XML 不允许 DTD / 外部实体；过深、超限、截断、重复 ID 和循环不会伪装成完整树。原始计划单元格读取上限 1 MiB，整体载荷 / 解码 / UI 节点另有预算。
