# Navidog 0.33 — 中文标点提示与同语句表名校验

编辑器对未引用代码中的中文逗号 / 顿号、全角分号 / 括号 / 点号 / 冒号及常见全角运算符给出精确红色标记、Unicode 编码和英文写法建议。普通中文名称继续可用；字符串、注释、美元引号 / Oracle q 字符串与各方言引用名称不做此检查。这属于编辑器的可疑标点检查，不宣称这些字符在所有方言名称中均非法。例如 [MySQL 标识符规则](https://dev.mysql.com/doc/refman/8.0/en/identifiers.html) 允许部分非 ASCII 字符出现在未引用标识符中，用户可显式引用包含标点的名称。

修复原文 `customer，` 导致当前 SELECT 解析失败后，`orders` / `customers` 的缺表提示再次被跳过的问题。先对原始语句编译；仅在失败且发现未引用的中文逗号时，创建只用于分析的副本，将逗号变成英文逗号并用空格保持 UTF-8 字节位置。辅助解析成功后只核对具有原始完整 token 边界的表名，不从修复副本推断字段、例程参数或修改执行 SQL；界面说明该语句仅辅助核对表名。原始 SQL、格式化输入、文件与撤销历史都不自动修改。

仍要求当前上下文的有效且完整元数据；离线、未验证与过期目录不会据此断言表不存在。DDL / 会话变更、临时对象与未知语句屏障保持保守处理。任意其他语法错误的完整容错绑定仍未覆盖，本版不把辅助分析描述成完整的 SQL 修复器。

回归覆盖用户完整原文（中文注释、中文逗号、JOIN 和末尾 `a`）、精确 UTF-16 标记、表名与逗号同时提示、表名带中文逗号不被拆成误报、emoji 前缀位置、各方言引用与字符串不误报、无元数据时仍提示标点，以及临时空 SQLite 库中的静默目录同步到编辑器标记的完整链路。业务库不用于测试。
