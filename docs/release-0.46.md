# Navidog 0.46.0：排序证明规则与执行计划表格

本轮增加两个原生 Hep 规则，对应 Calcite 固定 1.42.0 库存中 SortRemoveRedundantRule / SortRemoveDuplicateKeysRule 的受限同类行为。自主实现公开算法概念，没有逐行翻译 Java 源码，也不宣称完整规则或 API 兼容。库存中这两项记为 partial-analogue；已有九项同类子集，加本轮两项共十一项，不是规则数量完成度或功能百分比。

## 有证明前提的归约

HepSortLimitRemove 只用关系元数据的硬上界：输入最多一行、输入 / 排序键没有已知求值影响时，可移除冗余 Sort；纯输入的硬最大行数不超过正整数 LIMIT 且 OFFSET 为零时，可移除该 Limit。统计估计即使只有一行，也不作为证明。LIMIT 0、非零 OFFSET、动态界限、随机函数和可能报错的排序表达式保留。

硬行数与 LIMIT 使用整数比较，避免在 2^53 以上转 double 后把“多一行”误当相等。既有相邻重复 Sort 的消除也增加纯排序键前提。前后节点及原 Model 保持不变，归约追加新 DAG 节点；现有基线、预算、取消和规则轨迹继续有效。

HepSortDuplicateKeys 仅合并解析到同一作用域 / 表 / 列绑定的重复键，并处理直接输出别名。保留首次出现的排序方向和 NULL 顺序；后面的相反方向只在完全相同的键值关系中才冗余。未知列、任意同名函数、不同表的字段和一般派生表达式等价不作推断。没有实现上游全部字段等价推理或额外投影裁剪。

这是本地关系计划 / 建议的归约，不会自动改写或执行编辑器 SQL。实际 SQL 仍交给对应数据库驱动，缺少证明时保留原结构。

## 验证

增加硬上界 / 统计估计分离、OFFSET / 零 LIMIT / 求值影响、直接别名与绑定身份、首键方向 / NULL 顺序、源模型不变、2^53 整数边界的回归。GUI 覆盖常用列顺序、数值排序、详情开关与请求 / 原文模式。

临时 PG 测试比较带 NULL 和不同方向重复键的参考简化 SQL 结果，并确认相应本地规则被匹配；常量单行排序 / LIMIT 与不简化 OFFSET 的结果也有实际对照。原生优化器没有新的 SQL 反向生成器，所以该参考 SQL 对照不被描述为自动优化 SQL 的执行验收。
