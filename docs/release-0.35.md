# Navidog 0.35 — 上下文 SQL 补全

SQL 编辑器增加表、视图、Schema、字段、查询别名、函数、存储过程、局部变量、关键字、类型和建对象模板候选。表 / 例程来自当前上下文的本地元数据快照；输入过程中不连接数据库。查询页和对象定义编辑器共享实现。

- FROM / JOIN / UPDATE / INTO / REFERENCES 等位置优先补表；别名后补列，相关子查询可使用外层别名，最近同名别名遮蔽外层。支持已解析 CTE、派生表的列别名；同名字段提供限定名称。
- CALL / EXEC 位置补过程；表达式补函数和方言内建名称；过程体可补已声明参数 / 局部变量，SQL Server 保留 `@`，名称引用按方言转义。
- CREATE TABLE / VIEW / FUNCTION / PROCEDURE / TRIGGER 模板按方言生成，SQLite 不提供不存在的存储过程 / SQL 函数定义；选择后定位并选中对象名。模板中的表、字段、被调函数等占位名称仍需填写，模板不自动执行。
- 候选显示类别和来源 / 参数数量 / 字段粗类型。支持 quoted identifier、中文与 emoji 的 UTF-8 / UTF-16 范围转换；字符串、注释及各方言未闭合字符串中不补全。
- 默认输入两字符、限定名的点号或特定子句后触发；设置 → SQL 编辑器可关闭自动弹出或修改最短前缀。Ctrl+Space 手动触发；自动候选尚未手动选择时 Enter 仍换行，方向键选择后或显式请求后可 Enter 确认，Tab 接受候选。插入可一次撤销。

不是固定全局词表：优先解析带分析标记的 SQL，读取 owning Model 的作用域 / 目录定义；未完成语句有受限 token 回退。并非所有不完整语句、过程语言、跨多语句临时定义、服务器特定函数签名与版本均已覆盖；SQL 仍由服务端最终验证。完整目录尚未载入时仅提供可证实的本地候选；缓存候选标明 cached，不作为对象存在性的断言。

每个编辑器最多一个补全任务，全局两个 worker / 四个接纳槽；单次最多 256 KiB、128 个显示候选，协作式 200ms 预算。光标、文本、连接、数据库、Schema 或快照变化会取消 / 丢弃旧结果。原来缺少数据库 / Schema 身份的树名称列表不再混入其他上下文。

修复补全后改编辑器设置、清空并重新输入可能导致的光标内存错误：高亮更新合并到文档编辑完成后的事件轮次，补全弹窗关闭也避免同步焦点重入。对应场景经过连续重复、GuardMalloc 和 AddressSanitizer（含关闭 quarantine）验证。

另外拒绝把 MySQL / SQL Server 过程里的裸 SELECT 结果集直接放入 PG / Oracle 过程；目标需要 INTO / PERFORM / REF CURSOR 或改变返回签名，不能只重写关键字。

回归包括编译库作用域 / 遮蔽 / CTE / 派生表 / 目录隔离、各方言模板和字符串边界、GUI 插入 / 模板选择 / 一次撤销 / 连接失效 / 自动 Enter / 设置，以及现有隔离 PG / MySQL 功能。Oracle / SQL Server 没有本版服务端验收，Win7 运行回归仍待验证。

0.35.1 增加输入法提交事件的补全触发（包括 macOS / 中文输入法），显式选择首个候选，回归改为通过 Tab / Enter 实际接受候选，另提供“编辑 → 补全 SQL”以避开操作系统占用的快捷键。
