## 按语境的其他对象

`CatalogObjectKind` 增加独立、有界的正向对象枚举，不把列举不到当作不存在。DROP / ALTER / COMMENT / REFRESH 等按对象类型筛选；USE 选择数据库，类型槽位可补全自定义类型 / Schema，CREATE 按方言提供对象关键字及可用模板。

在已有表 / 列 / 别名 / 函数 / 过程 / 变量 / 参数基础上，增加可见数据库、Schema、索引、序列、触发器、物化视图、类型、同义词、包和事件等候选。具体来源依数据库能力与权限：

| 数据库 | 新增后台正向目录 |
| --- | --- |
| PostgreSQL | 数据库、Schema、索引、序列、触发器、自定义 / 复合类型；物化视图保留独立类别并可作为关系绑定 |
| SQLite | main、显式索引、触发器；忽略内部自动索引 |
| MySQL family | 可见数据库、索引、触发器、事件；未伪称支持 MySQL 中不存在的序列 / 类型等对象 |
| Oracle | 当前 owner 的索引、序列、触发器、类型、同义词、包及可见用户名称 |
| SQL Server | 数据库、Schema、索引、序列、触发器、自定义类型、同义词 |

只读本地不可变快照。新候选由后台有界批量查询加入原有 SQLite 原子快照，不在每次打字时查服务器；权限 / 版本 / 时间导致额外采集失败，不影响已独立完成的表 / 列 / 例程检查。旧缓存没有这些候选时，连接后的原静默刷新会逐步更新。

脚本中的已覆盖 CREATE / DROP INDEX、SEQUENCE 进入操作内 `ScriptContext`，不执行脚本。索引的命名空间考虑目标表归属，避免 MySQL / SQL Server 的不同表同名索引互相覆盖。namespace / 事务等旧失效屏障继续生效。DROP 函数候选不插入调用括号，SQL Server EXEC 过程候选也不插入不适用的括号。

这里是名称 / 上下文补全扩展，不代表包成员、所有对象 DDL、参数类型重载和全部过程语言均已解析完整。

## Parser → AST → IR → 语义 → SQL

新增 PG / Oracle / SQL Server 的 GROUPING SETS / ROLLUP / CUBE 和 MySQL-family WITH ROLLUP 前端；MySQL-family 普通 CUBE / GROUPING SETS 明确未覆盖，不因为某个展开结果碰巧等价就接受其源语法。MySQL 规范生成使用广泛适用的 WITH ROLLUP。

AST 与拥有数据的 Model 保存有序分组集合、重复集合与显式空集合；`groupBy` 作为绑定用表达式并集。默认整个编译操作最多展开 256 个集合和 8192 个引用，并保留嵌套 / 取消预算。普通括号表达式、比较 / IS NULL 及标量子查询仍走原表达式 Parser，不误当成分组元组。

GROUPING 的参数、位置与分组成员检查进入语义层。主键函数依赖须考虑所有集合共同保留的键；不能根据某个集合含主键就放行其他未分组字段。粗粒度类型系统仍未表达完整可空性 / 精度等事实。

目标支持时生成显式 GROUPING SETS，保留重复组并重新解析目标 SQL；MySQL 只生成可以按前缀汇总证明的 WITH ROLLUP，其他模式明确拒绝，不自动展开成可能改变求值 / NULL / 重复行语义的 UNION。SQLite 目标拒绝分组集合。

**本地成本规划暂不处理多组聚合。** 此类查询有明确诊断，不用普通单组聚合行数冒充结果；这不是 AggregateGroupingSetsToUnionRule 或 Calcite 全量移植完成。完整状态见 [Calcite 清单](calcite-port.md)。
