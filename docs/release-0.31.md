# Navidog 0.31：统一 SQLite 工作区与静默校验

本地数据集中到工作区 `navidog.sqlite`。`app_documents` 存放连接 / 分组、应用设置、标签与 SQL 草稿、表视图设置的版本化文档；`connection_secrets` 单独存放加密凭据；元数据继续使用结构化 scopes / objects / members 表、索引与过期机制。单次文档上限 8 MiB，凭据密文上限 64 KiB；WAL、事务、文件权限与写入等待上限保持受控。

首次读取自动导入原 connections.json、settings.json / sql-format.yaml、session.json 和 table-settings.json，原文件保留作为迁移来源与回退材料，迁移完成后以 SQLite 为准。旧元数据属于可重建缓存，在已连接的数据库上静默重新采集，不需要导入陈旧缓存。默认仍恢复上次标签和草稿。

编辑连接恢复“记住密码（本机加密）”复选框。只有显式勾选的数据库、SSH 密码 / 私钥口令、HTTP 验证密码才持久化；不勾选的凭据仍仅限本次运行。连接文档不含密码明文，凭据保存与连接配置在同一个 SQLite 事务内更新；取消记住或删除连接会删除对应密文。编辑、改名和后台更新服务器信息不应覆盖尚未加载的已保存密码。

不使用 macOS 钥匙串或 Windows 凭据管理器。macOS 使用 CommonCrypto AES-256-CBC 与 Encrypt-then-MAC（HMAC-SHA256，独立随机密钥），随机 IV，认证包含连接 ID，载荷绑定连接身份。密钥独立保存在同目录 `navidog.sqlite.key`，文件权限 0600；密文写入 SQLite。Linux 使用 OpenSSL 实现同一封装。Windows 使用用户范围 DPAPI、连接 ID 附加熵与禁止 UI 标志，不保存独立密钥文件。不能把这个机制当作对同账户恶意程序的隔离；备份 / 移动 Mac 密码需要同时保留 SQLite 和密钥文件。丢失密钥时不能恢复原密码，不能降级读取明文。

移除同步元数据按钮。连接建立、切换当前查询、编辑 SQL、缓存读取结束和后台周期检查会合并触发刷新；只对已有连接自动采集，不擅自打开用户未连接的数据库。后台刷新不占用前台查询的 busy 标志；元数据使用独立工作线程和短生命周期连接，不与导航树 / 对象操作共用队列，查询仍使用各自的工作线程。失败退避重试，不弹密码或系统授权窗口，不运行用户编辑器中的 SQL。字段 / 表校验只使用有效且完整的当前快照；未连接 / 待验证 / 刷新失败时清晰标记未校验，避免误报不存在。

MySQL / MariaDB / OceanBase 不再显示重复且不能独立切换的 Schema 框；PG / Oracle 保留有意义的 Schema 选择。统一 Select 控件绘制可见下拉箭头，覆盖可编辑与普通下拉。缺失表标记收窄到真实表名（不包括别名）；当前截图的 abc / cccc 与别名 c.df 错误分别由元数据和本地绑定诊断显示。

验证日志 `.cache/sql31-*.log`：临时库覆盖配置迁移与原文件保留、草稿恢复、密码加密保存 / 恢复 / 篡改拒绝 / 取消记住、事务回滚、后台同步与前台查询并行、元数据被锁等待时导航树仍能读取，以及精确表名标记。测试仅使用项目临时库 / 隔离 PG 和 MySQL；Oracle / SQL Server 本轮未连实例。Win7 SQLite 版完成交叉构建和 10 个 PE 文件依赖审计，尚未完成 0.31 客户机运行验收。

参考：本机 Apple SDK 的 CommonCrypto 头文件；[Microsoft CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。
