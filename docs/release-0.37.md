# Navidog 0.37：脚本上下文、MERGE 与转换语义

本版继续扩展独立 C++ 编译库和桌面入口。0.36 的本地关系代数 / Memo / 物理候选 / 成本、设置与服务端估计计划继续保留，见 [0.36](release-0.36.md) 和 [优化器设计](optimizer-design.md)。这是按 Calcite / Volcano 核心思路编写的 C++ 实现，并非完整移植 Calcite Java 框架，也没有引入 LLVM 运行时。

## 脚本声明与上下文

新增 `ScriptContext`，在一次分析操作中将脚本已声明的对象覆盖到不可变目录快照上。不访问网络、不执行 DDL、不改服务端或长期缓存。

- 支持已覆盖的 CREATE TABLE / CTAS / LIKE / VIEW、ALTER 的常见字段动作、DROP；后续语句按顺序检查字段和已知例程参数个数。`IF NOT EXISTS`、未知来源形状、CASCADE、CALL 和未建模的会话 / 事务变化保持保守。
- 前面 SELECT 的错误不会被后面 CREATE 同名表反向消除。事务执行时间线、所有依赖关系及所有 DDL 属性尚未完整建模。
- 编辑器诊断、脚本检查、转换、查询页“解析 AST”及执行前辅助报告分别创建操作内上下文。查询分析只继承脚本的假定声明，不自动连接数据库。
- 补全先处理光标前已完成的语句，再分析光标所在的语句 / 例程；原文坐标保持不变。前面创建的表、字段和函数可参与提示，支持正常的 DELIMITER / GO / Oracle 斜线分隔。未完成引号仍使用原有容错扫描，不承诺所有破损脚本都能恢复。
- 参数、局部变量、SQL 条件、过程条件和过程标量使用不同的语义环境；Oracle PL/SQL BOOLEAN 与 Oracle 19c SQL、SQL Server BIT 与条件分别处理。

声明上下文限制对象 / 例程数量和累计 8 MiB；例程 lowering 对复制的作用域与模型设累计 16 MiB 预算。JSON 报告使用有界输出，支持取消；这些是工程预算，并非进程 RSS 的硬上限。

## MERGE

新增语句、ON、匹配类别、条件、赋值 / 插入 / 删除 / 不操作等类型化 AST / IR 节点。分别实现 PostgreSQL 15、Oracle 19c、SQL Server 旧版本语法基线的受支持分支：

- PG 条件分支、UPDATE / DELETE / INSERT / DEFAULT VALUES / DO NOTHING、不可达分支检查。
- Oracle 单类分支、UPDATE / INSERT WHERE、更新后 DELETE WHERE 的独立阶段；禁止更新已证明由 ON 引用的目标列。
- SQL Server TOP、BY TARGET / BY SOURCE、分支数量 / 顺序 / 动作组合和必需的结束分号。
- ON 与分支的来源 / 目标可见范围分别绑定；检查重复赋值、插入字段和已知目录对象。编辑器会检查目标表和来源表。
- 同方言生成、目标重新解析与格式化；过程内嵌入 MERGE 使用相应 SQL 上下文。

SQL Server 的执行、执行计划、初始化语句和本地分析统一保留原文中已有的结束分号；不会补造缺失分号。`CREATE PROC` 别名的程序解析与客户端分句也已补齐。

跨方言 MERGE 仍明确拒绝：唯一性、重复匹配、并发、触发器及更新后删除阶段需要更多证明。本地成本模型也明确报告 MERGE 未覆盖，不输出伪造的物理成本。OUTPUT / RETURNING 等扩展并未全部实现。

## 聚合、条件与表达式

- `inspectQueryFeatures` 从统一 Model 分析查询块的普通聚合与窗口，区分窗口外层调用与参数 / 排序中的聚合；语义、转换和本地计划共享这一分析。
- PG / Oracle / SQL Server 检查已能证明的未分组列、聚合输出、HAVING、窗口键和 GROUP BY 序号；PG 的脚本内非延迟主键可用于函数依赖。CTE / 派生表不继承该例外。服务端目录尚未采集完整主键事实，因此对不能证明的基表依赖暂缓否定判断；未知函数可能是自定义聚合，其参数也不做确定的错误判断。
- MySQL 的 SQL mode 未被凭空假定为 ONLY_FULL_GROUP_BY，SQLite 的裸列规则保持独立。SQLite 已知非聚合 HAVING 会提示；未知聚合函数保守处理。
- HAVING 无显式分组 / 聚合时，区分 MySQL 的逐行过滤与 PG 等的隐式单组；本地计划保留相应过滤和行数，跨两类方言时拒绝直接替换语法。
- PG `IS [NOT] DISTINCT FROM`、`NOT ILIKE` 的解析、生成、格式化和已知 NULL 选择率；跨方言缺少证明的映射明确拒绝。
- 生成器保留嵌套比较的必要括号，避免把 `(a=b)=TRUE` 展平成非法或不同结构的比较链。
- 非 MySQL / SQLite 基线的重复 SET 目标报错；MySQL / SQLite 已有不同的重复赋值规则，不一概禁止。

这是分层的基础语义分析，尚无完整隐式转换、用户聚合属性、函数重载、排序规则、权限和版本能力矩阵。通过本地检查不能替代服务器校验。

## 转换与例程报告

函数 / 过程增加 ELSIF / ELSEIF 链与 SQL Server 可省略分号的 BEGIN / END 块；目标生成保持块结构，使用深度、访问次数、取消和输出预算。

查询页 AST 现在显示例程名称、作用域树、参数 / 变量类型、符号绑定、程序节点及其内部表达式 / SQL Model，支持源码范围定位。报告过大时明确标记展示截断；原 SQL 执行文本不会换成生成文本。

补充 UPDATE 赋值依赖分析：MySQL 后面的 RHS 可能读取前面已更新的列，PG 等使用旧行。检测到直接、表达式或已覆盖子查询中的依赖时拒绝跨这两类方言转换；不通过重排或未经证明的临时值“修复”语义。原有目标重新解析、DDL 事务审核和整批原子输出继续生效。

精确转换仍是对明确覆盖并通过检查的构造提供结果，不能宣称任意 SQL 都能等价转换。游标、异常、动态 SQL、包、完整触发器转换、递归 CTE、复杂类型和完整控制流分析仍未完成。

## 服务端估计计划

算子树增加搜索（算子 / 对象 / 索引 / 条件）、保留匹配祖先、展开 / 收起和数字排序。结构化 JSON、原始文档和原网格继续可用。

Oracle / SQLite 缺失父节点和自环不再被包装成完整计划；SQL Server 在单个 QueryPlan 内检查重复 NodeId，不同 QueryPlan 可重复使用编号。继续限制 XML 实体、深度、节点数和载荷。

仍使用独立会话读取估计计划，不运行 EXPLAIN ANALYZE，也没有将估计成本称为实际耗时。完整的服务器计划警告解读和实际计划采集尚未完成。

## 0.37.1 边界与常量过滤补充

- 排序 / 分组序号绑定到对应的 SELECT 输出，供分组检查、类型族和排序 / NDV 成本分析共用；保留源码中的数字写法。同方言输出不替换原文，跨到不支持 GROUP BY 序号的目标时展开已确认的投影。无法确认 `*` 展开时拒绝不安全转换。
- PG 的序号越界、负序号、非整数常量和 SELECT DISTINCT 的已能确认的排序表达式不在输出列表等情况增加诊断。类型别名、限定函数、子查询身份需要更丰富目录信息，不能按原始名字或 arena ID 断言表达式不同；这类情况暂缓否定判断。
- 独立临时 PostgreSQL 的 41 个边界语句中，本地接受 / 拒绝与服务器一致，成功生成的规范 SQL 另与源查询比对结果。正式回归增加相应序号 / DISTINCT 用例。这只覆盖列举的样本，不能外推为完整语法等价证明。
- 本地 Memo 新增 `FilterRemoveTrue` 与 `FilterToEmpty` 候选和常量条件建议。精确域只包含受限短整数字面量、布尔 / NULL、已覆盖的空值检测、比较和三值逻辑；不调用函数、不做浮点近似、不折叠子查询 / CAST 或依赖排序规则的字符串比较。恒假 / UNKNOWN 的空结果化简仅在直接纯表 / 常量来源应用；不跨聚合、窗口、修改或其他复杂来源删除执行结构。仍不执行或修改原 SQL。
- “过滤优化”开关同时控制过滤下推与上述常量规则。规则事件保留在报告和界面，说明可在规则页核对；成本仍为相对估计，不是服务器实际耗时。
